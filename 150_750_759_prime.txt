Prime 150, Prime 750 and Monthly 759 – Simple Flow (in plain English)

Prime package approval vs coupon activation (very important)
- Prime packages (150/750) purchased from the Consumer Promo Packages screen are activated at ADMIN APPROVAL. Commissions are distributed at approval time. No e‑coupon is created and no “Activate Coupon” click is required for Prime packages in this flow.
- Coupon-based flows are different and use coupon create/activate events as the trigger; that is not used for Prime packages purchased via Promo Packages.
- This keeps Prime package activation simple: consumer submits payment -> admin approves -> payouts are processed using your Admin Commission settings.

Where the amounts come from
- No hard-coded rupee values are used.
- All amounts come from the Admin commission configuration (AdminCommissionDistribute). The system reads from a single master commission JSON in the backend.
- For Prime 750, 750-specific overrides in Admin are disabled. The system ALWAYS uses Prime 150 values multiplied by 5 (multiplier = 5) for both package and e‑coupon flows.
- If required values are missing or invalid, the payout is stopped and nothing is credited (to avoid wrong payouts).

What happens when a user starts Prime 750 and Admin approves
1) Admin approval event
   - The system treats this as a Prime 750 activation.
   - It uses the Commission Policy and Admin config to decide amounts.

2) Direct bonus to sponsor and self bonus to the user
   - The sponsor (the person who referred the user) gets a direct bonus.
   - The user themself gets a self bonus.
   - For Prime 750 these values are fixed as Prime 150 values × 5 (no 750-specific override; multiplier = 5).
   - These credits go to the users’ money wallets as transactions named PRIME_750_DIRECT (sponsor) and PRIME_750_SELF (user).

3) Agency/Geo distribution (regional/upline payout)
   - The system derives the 750 base amount strictly as (Prime 150 base amount × 5). Admin 750-specific base is not used.
   - With that base amount, it triggers agency/geo distribution for “750”. This pays configured agency/upline beneficiaries per your Admin setup.

4) Matrix participation (5-matrix and 3-matrix)
   - The system opens matrix accounts for the user (both 5-matrix and 3-matrix).
   - The number of entries is scaled by 5 (it reuses the Prime 150 “coupon activation count”, multiplied by 5).
   - This makes the user eligible for matrix earnings as per your matrix settings.

5) Reward points
   - The user gets reward points for the 750 activation. The points are scaled from the Prime 150 reward points by 5.

6) First activation stamp (if not already set for this user)
   - On first-ever activation, the system:
     - marks the account as active,
     - enables autopool and rewards,
     - unlocks agency benefits and allows the user to create self-accounts,
     - and releases any pending wallet ledger for the account.
   - This is idempotent (runs only once for a user).

7) Audit and safety
   - Every wallet credit stores simple “source” data (type and id) so you can trace where it came from.
   - If configuration is missing or invalid, the system stops payouts to prevent mistakes.

What happens when a user activates Prime 150 and Admin approves
1) Direct and self bonuses
   - Sponsor gets PRIME_150_DIRECT and the user gets PRIME_150_SELF, using amounts set in Admin config for Prime 150.

2) Agency/Geo distribution
   - Uses the configured Prime 150 base amount and pays agency/upline per settings.

3) Matrix participation
   - Opens 5-matrix and 3-matrix accounts for the user based on the configured “activation count”.
   - This enables matrix earnings according to your matrix configuration.

4) Reward points
   - The user gets reward points for Prime 150 activation (amount configured in policy).

5) First activation stamp (if first time)
   - Same first-time activation effects as noted above (account active, autopool, rewards, agency unlocks, etc.).

What happens in Monthly 759 (first month or recurring month)
1) Strict configuration
   - Monthly 759 requires all values to be present in Admin config (base amount, whether agency distribution is enabled, and fixed amounts for each level). Missing values stop payouts.

2) Direct sponsor and (optional) self bonus
   - Sponsor receives MONTHLY_759_DIRECT.
   - The user can also receive MONTHLY_759_SELF if it’s explicitly configured.

3) Fixed level payouts (L1 to L5)
   - Pays fixed amounts to upline levels 1 to 5 (not percentages). Amounts are taken directly from Admin config.

4) Agency/Geo distribution
   - If monthly 759 says agency is enabled, it triggers agency/geo payouts using the configured monthly base amount for “759”.

5) Reward points
   - The user gets reward points equal to the configured monthly 759 base amount.

Useful notes and guardrails
- Idempotent actions: The system avoids duplicating activations and matrix distributions for the same source/coupon.
- Audit trail: All credits include simple metadata (source type and id) for auditability.
- Agency in matrix: There is an admin toggle to allow or block matrix payouts going to agency/employee accounts. If it’s off, those recipients are skipped for matrix earnings.
- Everything is config-driven: If required config is missing, payouts stop instead of guessing values.

In very short
- Prime 150: Sponsor gets money, user gets money, agency/upline gets money, matrix accounts open, user gets points, and first-time activation unlocks benefits.
- Prime 750: Same as Prime 150 but all amounts are scaled from 150 by 5 (no 750-specific config). Matrix entries also scale by 5.
- Monthly 759: Sponsor (and optionally the user) get money, fixed level payouts (L1–L5) happen, optional agency/upline payout happens if enabled, and user gets points equal to the monthly base amount.

After Admin approves a Prime 750 request in the Promo/Packages screen, the system immediately applies the above Prime 750 steps for that user, using your Admin-configured values and recording everything with simple audit metadata.

Numeric example for a ₹750 Prime activation (assuming multiplier = 5 and current Prime 150 config)
- Prime 150 direct sponsor: ₹15.00 → 750 sponsor direct = ₹75.00
- Prime 150 self bonus: ₹1.00 → 750 self bonus = ₹5.00
- Agency/Geo (fixed mode) per activation (each 150 amount × 5):
  - Sub Franchise: ₹15 × 5 = ₹75
  - Pincode: ₹4 × 5 = ₹20
  - Pincode Coordinator: ₹2 × 5 = ₹10
  - District: ₹1 × 5 = ₹5
  - District Coordinator: ₹1 × 5 = ₹5
  - State: ₹1 × 5 = ₹5
  - State Coordinator: ₹1 × 5 = ₹5
  - Employee: ₹2 × 5 = ₹10
  - Admin (Company/Royalty): ₹10 × 5 = ₹50
- Immediate wallet credits at approval (excluding future matrix earnings): ₹265.00

Matrix openings for ₹750 (from Prime 150 activation_count = 1 → 1 × 5)
- 5-Matrix: 5 entries, each entry amount recorded = ₹750
- 3-Matrix: 5 entries, each entry amount recorded = ₹750
- Note: Matrix earnings are paid later as the matrices fill per your configured amounts/percents; the above shows entry creation, not future earnings.

Reward points
- Prime 150 reward points = 0 → 750 reward points = 0

Admin UI quick steps to make reward points go to wallet (Total reward points)
- For Prime 150 and 750:
  - Go to Admin → Commission Distribution → ₹150 Activation — Reward Points.
  - Set “Reward Points (150)” to a positive number and Save.
  - Effect: Prime 150 credits exactly this value; Prime 750 credits 5 × this value automatically.
- For Monthly 759:
  - Go to Admin → Commission Distribution → ₹759 Activation → “₹759 Monthly — Reward Points (Base Amount)”.
  - Set “Base Amount (₹)” and Save.
  - Effect: Monthly 759 credits reward points equal to this Base Amount each month.
